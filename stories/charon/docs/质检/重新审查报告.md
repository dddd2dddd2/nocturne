## 一、逻辑悖论（P0，需改图）

### P0-1　ENDING_04「净舱」双入口自相矛盾
- 公式（`结局/ENDING_04_净舱.md`）要求 `[洞察] < 40`。
- 但节点路径 `NODE_205（真相揭晓，需 [洞察]≥40）→ NODE_207（交权）→ ENDING_04` 要求 `[洞察] ≥ 40`。
- 同一条结局有两条入口：`NODE_202 A 失败 → NODE_211 → ENDING_04`（洞察<40，与公式一致）与 `205→207→ENDING_04`（洞察≥40，与公式矛盾）。
- **修复**：净舱只保留 `202→211` 一条入口；`207 交权` 改为通向其他结局（如并入 ENDING_05/新结局），或把 ENDING_04 公式拆成两个结局。

### P0-2　NODE_011 B「反悔」与 NODE_013 门槛不匹配
- `NODE_011 B` 反悔门槛 `[洞察] ≥ 15`，成功后 `[洞察]+5`。
- `NODE_013` 自身入场门槛 `[洞察] ≥ 25`。
- 当 `洞察∈[15,19]` 时，反悔后洞察为 20–24，仍 `<25`，却已进入 NODE_013 → **非法进入深层觉醒**。
- **修复**：`NODE_011 B` 门槛改为 `≥20`（反悔 +5 后恰好 ≥25），或把 NODE_013 门槛降为 `≥20`。

### P0-3　「伪HE」未纳入结局体系
- `NODE_011 A「接受裁决」` 的剧情是"裴延认罪、NORA 静默接管"（伪HE），与 `ENDING_02 沉默的幸存者`（重启推进器返航）是**两个不同结局**。
- 但 8 个结局文件里没有"伪HE"，JSON 里把它并进了 End_2 → **结局编号体系少了一个真实结局**。
- **修复**：给伪HE 分配正式编号（如 `ENDING_02A`），或在 ENDING_02 文件内注明"含两种变体（伪HE / 幸存返航）"。

## 二、死循环 / 可刷取（P1）

### P1-1　NODE_005 C「追向天线区」可无限刷 SAN
- markdown 中该选项**无 guard**：`005 C → SAN-10 → 返回 002 → 005 C → …`，可连刷 8 次把 SAN 从 100 刷到 <20 触发 NODE_012。
- JSON 已给它加 loop_guard，但 markdown 未同步 → **文档漂移 + 可刷取漏洞**。
- **修复**：markdown 标「仅首次有效」，与 JSON 一致。

### P1-2　NODE_010「对质（他戒备你）」构成低代价回环
- `010 C-else（裴延≤2，第一幕恒真）→ 002 → 003/004 → 010` 可循环；clue 单调递增最终会突破 25，非无限，但 bond 被反复洗到 0，且玩家必须借"裴延戒备你"这个叙事别扭的选项才能回枢纽拿 008 修复痕。
- **修复**：给"对质（戒备）"也加 guard；或提供一条显式的"返回指挥舱"选项。

## 三、孤岛 / 悬空（P1）

### P1-3　NODE_112（第二幕坏结局）无显式入口
- 前置写的是"触发条件"（风暴独自行动且 SAN<20 / 投票被反噬），但**全图没有任何选项指向 NODE_112**，mermaid 里也是虚线 `N105 -.-> N112`。
- **修复**：在 NODE_106（投票处决）或风暴节点加一个明确 `→ NODE_112` 的选项。

### P1-4　NODE_012 在 JSON 中被删并（文档不一致）
- markdown 中 NODE_012 可达（005 C 触发），但 JSON 里被并入 `Node_3_3 → End_5`。
- 两份文档对"第一幕坏结局"的建模不一致。
- **修复**：JSON 补 `Node_1_12`，或 markdown 明确注明合并关系（当前仅 README 一句带过）。

### P1-5　「存活NPC ≥ 4」缺少变量支撑
- `ENDING_02` 公式要求 `存活NPC ≥ 4`，NODE_105「变量死亡」也依赖"谁死了"。
- 但全篇**没有 `[存活_XX]` 旗标或存活计数变量**——这个条件无法被结算。
- **修复**：引入 `[存活_NPC]` 数组/计数，并定义 NODE_105 的死亡映射（哪个选择导致谁死）。

## 四、变量 / 文档漂移（P2）

### P2-1　两套初始值
- markdown：`SAN=100, NORA=10`；JSON 引擎：`sanity=70, 无 NORA 轴`。
- **修复**：统一基准，或在 README 明确声明 JSON 是"降维审计模型"（已部分注明，需补 SAN 70/100 差异）。

### P2-2　ENDING_01「三线索齐」被压成 clue≥60
- 公式要求"0.7秒空隙 + 修复痕 + 假死迹象"**三项**齐备；JSON 只校验 `clue≥60`（总和），无法验证**精确组合**。
- 且引擎 `_meets` 只支持 clue 总和，不支持 `clue_a_min / clue_b_min / clue_c_min` 分项门槛。
- **修复**：扩展引擎 condition 支持分项 clue 门槛，再在 JSON 里精确建模三线索。

### P2-3　JSON 的 SAN<30 全局强制跳转在 markdown 无对应
- 引擎规则"任一选项后 SAN<30 → 强制 Node_3_3"在 markdown 里不存在（markdown 只有 SAN<20→NODE_012）。
- 且 `Node_3_3 挣扎 → Node_1_2` 会把第三幕的玩家"传送"回第一幕枢纽 → 时序悖论（简化模型可接受，但需标注）。

### P2-4　NODE_105「变量死亡」映射未定义
- NODE_014 结算写"若玩家把 [线索_...] 交给过某人，该 NPC 当夜行动线被改写"，但**没有任何选项定义"把线索交给某人"的动作**，死亡映射是黑盒。
- **修复**：补"交付线索"选项，或删除该结算描述。
