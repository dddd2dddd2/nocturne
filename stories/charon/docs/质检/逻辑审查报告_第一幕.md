# 《卡戎回声》节点网络 · 逻辑审查报告

- **审查对象**：`节点/01_第一幕_Day1节点架构.md`（NODE_001~014）＋ `结局/`（8 个结局判定公式）
- **审查人视角**：游戏逻辑架构质检 / 静态代码分析员
- **审查方法**：入度/出度分析、可达性分析、变量上界分析、线索来源（producer/consumer）分析

## 0. 总体结论

| 等级 | 数量 | 说明 |
|---|---|---|
| 🔴 P0 阻断性 | 7 | 结局/节点数学上不可达、线索无来源、门槛超变量上界 |
| 🟠 P1 逻辑缺陷 | 5 | 无限刷取循环、else 分支未定义、条件互斥 |
| 🟡 P2 一致性/规范 | 3 | 初始值未声明、返回边非显式、悬挂引用 |

**根因**：`节点/README.md` 与 `结局/README.md` 均未声明变量**初始值**，且多个"门槛"（NORA≥10、信任≥N）引用了**没有任何产出源**的变量——这是本次发现的大部分 P0 问题的共同源头。

## 2. 死锁与无限回环检测

### 发现

- 🟠 **信任刷取循环 ①（002 ↔ 005）**：`NODE_002 B(+沈棠1) → NODE_005 B(+沈棠2, 返回002) → 循环`。每圈 +3 沈棠信任、**零消耗**，可无限刷满 → 摧毁 ENDING_05 的"沈棠信任≥6"难度。
- 🟠 **洞察刷取循环 ②（010 C 自环）**：`NODE_010 C` 满足裴延≥3 时 `+洞察5` 后"再回本节点"，未标注"仅首次有效" → 可无限刷洞察，直接冲垮 ENDING_01 的 `洞察≥60` 与 NODE_013 的 `洞察≥25` 门槛。
- 🟠 **else 分支未定义（软锁风险）**：
  - `NODE_010 B` 洞察<25 时"退回继续调查"——**目标节点未指定**（回到 002？还是原地？），玩家可能卡在无出口状态。
  - `NODE_010 C` 裴延<3 时**无去向**。
- 🟡 **倒计时变量未接入**：大纲设定"时间即代价"，但第一幕没有任何节点消耗 `[倒计时]`（仅 NODE_014 一次性 -24h），导致"无限调查不付出代价"成为结构性漏洞——这是上述刷取循环的土壤。

## 3. 不可达结局（Dead-End Logic）

### 汇总表

| 结局 | 关键前置 | 判定 | 原因 |
|---|---|---|---|
| ENDING_01 真名 | 洞察≥60 ＋ 三线索齐 | 🔴 不可达 | 见下 |
| ENDING_03 与虎谋皮 | 白烬信任≥6 | 🔴 不可达 | 白烬信任无任何产出源 |
| ENDING_04 净舱 | NORA≥80 | 🔴 不可达 | 第一幕 NORA 上界约 +10 |
| ENDING_06 种子 | 童野信任≥8 | 🔴 不可达 | 第一幕童野信任上界 +3 |
| ENDING_08 观测者 | 全程"不授权" | 🔴 不可达 | 与 NODE_001 强制授权冲突 |
| ENDING_05 回声 | 沈棠信任≥6 且 洞察≥40 | 🟠 内部张力 | 高信任路径放弃 修复痕(+8) |
| ENDING_07 零 | 身份觉醒=回声体 | 🟠 不可计算 | 隐藏变量无判定规则 |

### 细节

1. 🔴 **ENDING_01（真名）双重阻断**：
   - **三线索互斥**：`[线索_0.7秒空隙]` 只能从 003 B → 007 获得；`[线索_假死迹象]` 只能从 004 → 009 获得；而 003 一旦选 B 就**不再经过 004**（007 出口是 010）。二者在单程路径下无法同时取得。
   - **洞察上界不足**：第一幕单程最大洞察约 `2+2+3+12+5=24`（001B+003C+004C+009A+010C），**连 NODE_013 的 `洞察≥25` 都差 1**；`洞察≥60` 需第二/三幕补足，而第二/三幕节点尚未定义。
2. 🔴 **ENDING_03**：全图无一节点写入 `[信任_白烬]`。
3. 🔴 **ENDING_04**：NORA 最大累计 ≈ +10（001A +5、013C +5），距 80 遥不可及。
4. 🔴 **ENDING_06**：童野信任仅 002C(+1)、006B(+2)，上界 +3，距 8 差 5。
5. 🔴 **ENDING_08**：NODE_001 的 A/B 两个选项**都会接受授权**，不存在"拒绝授权"路径 → "全程不授权"前提自相矛盾。
6. 🟠 **ENDING_05**：沈棠信任≥6 必须走 008 B（帮隐瞒，+3），但该选择**放弃** `[线索_修复痕]` 的 +8 洞察，与 `洞察≥40` 反向拉扯。
7. 🟠 **ENDING_07 / ENDING_01 的身份觉醒**：README 只写了语义描述（"总选最大化存续"），未定义**哪个节点的哪个选项计入判定**，两边门槛当前都无法计算。

## 4. 道具/线索时空悖论

### 发现

- 🔴 **`[线索_裴延行程空白]` 无产出源**：被 NODE_011 当作入场条件、被 NODE_010 C 当作"另一个版本"的前提，但**没有任何节点产生原版线索** → 玩家永远拿不到，NODE_011 实际进不去。
- 🔴 **`[线索_非周期脉冲]` 无产出源**：被 NODE_008 的入场条件引用（"需[线索_非周期脉冲] 或 [信任_沈棠≥3]"），但全图无节点产出 → 该线索是凭空引用。
- 🔴 **`[NORA]≥10` 在可达成之前被引用**：NODE_007 的门槛高于该时点的变量上界（见 §1）。
- 🟠 **`[信任_裴延]≥3` 无源**：NODE_010 C 引用了不存在的变量积累。
- 🟡 **线索发现顺序未约束**：NODE_008（修复痕）与 NODE_007（0.7秒空隙）本应是一对"0.7秒母题"的互补证据，但图中二者无任何前置关联，玩家可以只拿其一就进入深层线——逻辑上不悖论，但削弱了设计意图（三处 0.7 应可串联）。

## 5. 修复建议（连线修正方案）

> 按"最小改动 + 消除根因"排序。

### F1【根因】声明变量初始值（`节点/README.md`）
```
[洞察]=0  [SAN]=100  [倒计时]=72h  [NORA]=10（审计员自带基础授权）  全员信任=0
```
→ 直接使 NODE_007 的 `NORA≥10` 可达。

### F2【修互斥】NODE_007 出口改回主线
```
NODE_003 B → NODE_007 → NODE_004（回归主线，而非 NODE_010）
```
→ 修复"0.7秒空隙"与"假死迹象"三线索互斥，打通 ENDING_01。

### F3【修门槛】NODE_007 门槛放宽
`[NORA]≥10` → `[NORA]≥5`（配合 F1 亦可保留 10）。

### F4【补线索源】
- `NODE_003` 的 A、C 分支增加产出 `[线索_裴延行程空白]`（勘查门禁记录发现裴延 03:30 删除记录）。
- `NODE_005 A` 增加产出 `[线索_非周期脉冲]`。

### F5【补信任源】
- `NODE_002` 增加选项 D「先找白烬」→ 新增 **NODE_015 领航舱·逃生舱疑点**，产出 `[信任_白烬]`。
- 新增 **NODE_016 与裴延对质**，选项「提起他的女儿」产出 `[信任_裴延]`（顺带为 NODE_010 C 供能）。
- `NODE_006 B` 的童野信任 `+2 → +3`，并在第二/三幕补童野信任源；或将 ENDING_06 阈值 `≥8 → ≥5`。

### F6【修 NORA 上限】
新增"向 NORA 交权"动作节点（NODE_017）：`[NORA]+40`、代价 `[洞察]-5`；或将 ENDING_04 的 `NORA≥80 → NORA≥35`。

### F7【治回环】
- 统一「返回 NODE_002」为显式边，且每次 `[倒计时]-1h`。
- `NODE_005 B` 的 `[信任_沈棠+2]`、`NODE_010 C` 的 `[洞察+5]` 均标注**「仅首次有效」**。

### F8【补 else】
- `NODE_010 B` 失败 → 显式指向 `NODE_002`，`[NORA]-2`、`[倒计时]-1h`。
- `NODE_010 C` 若 `[信任_裴延]<3` → 对质失败，`[信任_裴延]-1`，返回 `NODE_002`。

### F9【重校准阈值】
- 在 `结局/README.md` 声明：**ENDING 判定为终局结算（跨三幕）**，第一幕只需保证 NODE_013 的 `洞察≥25` 可达。
- NODE_013 门槛：当前单程最大约 24，需在 004/006/007 增加洞察产出，或降为 `洞察≥20`。

### F10【修 NODE_001 与 ENDING_08 冲突】
`NODE_001` 增加选项 C「拒绝授权，独立调查」→ 无审计权限（NODE_007 等门槛提高一档），但满足 ENDING_08 的"不授权"前提。

### F11【修身份觉醒可计算】
在 README 定义判定规则：对含「牺牲个体保多数 / 交权 / 出卖」语义的选项打「理性解」标签，累计 N 次以上 → 回声体。

### F12【清悬挂】
`NODE_014 → NODE_101` 标注 TODO，并定义第二幕编号规范（`NODE_1xx`）。
